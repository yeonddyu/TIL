## 1. 프로젝트 만들고 실행하기

```bash
npm create vue@latest     # 프로젝트 생성 (Router, Pinia 선택)
cd vue-project
npm install               # package.json에 적힌 패키지 설치 → node_modules 생성
npm run dev               # 개발 서버 실행 → http://localhost:5173
```

### Django와 비교하면

| Vue | Django |
|---|---|
| `npm` | `pip` |
| `package.json` | `requirements.txt` |
| `npm install` | `pip install -r requirements.txt` |
| `npm run dev` | `python manage.py runserver` |
| `router/index.js` | `urls.py` |

- 코드를 저장하면 새로고침 없이 바로 화면에 반영된다 (**HMR**, Hot Module Replacement).
- **Node.js**: JavaScript를 브라우저 밖(내 컴퓨터)에서 실행하게 해 주는 환경
- **Vite**: 개발 서버를 띄우고, 나중에 배포용 파일로 빌드해 주는 도구

### package.json vs package-lock.json

| | package.json | package-lock.json |
|---|---|---|
| 기록하는 것 | 어떤 패키지를 쓰는지 + **버전 범위** | 실제 설치된 **정확한 버전** |
| 작성 | 사람이 직접 수정 가능 | npm이 자동 관리 |
| 예 | `"^3.5.0"` = 3.5.0 이상 4.0.0 미만 | `"3.5.13"` |
| Git에 올리기 | ✅ | ✅ (팀원 모두 같은 버전 설치) |

- `node_modules/` 폴더는 용량이 크고 `npm install`로 다시 만들 수 있어서 **Git에 올리지 않는다** (`.gitignore`).

## 2. Vue 앱이 화면에 나타나는 과정 (SPA)

**SPA (Single Page Application)**: HTML 파일 **하나**(`index.html`) 안에서 JS가 내용을 바꿔 끼우며 여러 페이지처럼 보이게 하는 방식.

```
index.html          <div id="app"></div> + <script src="/src/main.js">
   ↓
main.js             const app = createApp(App)   ← 최상위 컴포넌트로 앱 만들기
                    app.use(router)               ← 라우터 사용 등록
                    app.mount('#app')             ← id="app"인 div에 붙이기
   ↓
App.vue             전체 뼈대 (헤더, 네비게이션) + <RouterView />
   ↓
views/HomeView.vue  주소에 따라 RouterView 자리에 바뀌어 들어가는 화면
```

- `<RouterLink to="/about">`: 새로고침 없이 주소만 바꾸는 링크 (`<a>` 대신 사용)
- `<RouterView />`: 현재 주소에 맞는 컴포넌트가 들어갈 자리

## 3. 컴포넌트와 state

`.vue` 파일 하나 = **컴포넌트** 하나. 이름은 **PascalCase** (`HomeView.vue`, `TodoItem.vue`).

```vue
<script setup>
// JavaScript
</script>

<template>
  <!-- HTML -->
</template>

<style scoped>
/* CSS: scoped를 붙이면 이 컴포넌트에만 적용 */
</style>
```

### ref로 state 만들기

```vue
<script setup>
import { ref } from 'vue'

const nickname = ref('연주')
</script>

<template>
  <p>안녕하세요, {{ nickname }}님</p>
</template>
```

- **state**: 값이 바뀌면 **연결된 화면이 자동으로 다시 그려지는(렌더링)** 특별한 변수
- 일반 변수는 값이 바뀌어도 화면이 그대로다.

### `.value` 규칙 ⭐

| 위치 | 접근 방법 |
|---|---|
| `<script>` 안 | `nickname.value` |
| `<template>` 안 | `nickname` (`.value` 없이) |

```javascript
nickname.value = '하연주'   // script에서는 .value 필수
```

## 4. 문법 ① `{{ }}` — 텍스트 출력 (mustache)

```vue
<p>{{ nickname }}</p>
<p>{{ count * 2 }}</p>                         <!-- 간단한 JS 표현식 가능 -->
<p>{{ isLogin ? '로그아웃' : '로그인' }}</p>
```

- 콧수염 모양이라 mustache라고 부른다.
- 표현식(값이 나오는 코드)만 가능하고, `if`문이나 `for`문 같은 문장은 쓸 수 없다.

## 5. 문법 ② `v-model` — 입력값 ↔ state 양방향 연결

```vue
<script setup>
import { ref } from 'vue'

const keyword = ref('')
const agree = ref(false)
</script>

<template>
  <input type="text" v-model="keyword">
  <p>검색어: {{ keyword }}</p>

  <input type="checkbox" id="agree" v-model="agree">
  <label for="agree">약관 동의: {{ agree }}</label>
</template>
```

- **양방향 바인딩**: 입력하면 state가 바뀌고, state를 코드로 바꾸면 입력창도 바뀐다.
- 텍스트 입력은 문자열, 체크박스는 `true / false`로 연결된다.
- 지난주 JS에서는 `input` 이벤트 + `event.target.value` + `textContent`로 직접 했던 일을 `v-model` 하나로 처리한다.

## 6. 문법 ③ `v-on` / `@` — 이벤트 처리

```vue
<script setup>
import { ref } from 'vue'

const likes = ref(0)

function addLike() {
  likes.value += 1          // script 안이라 .value
}

function showKey(event) {
  console.log(event.key, event.target.value)
}
</script>

<template>
  <button v-on:click="addLike">좋아요 {{ likes }}</button>
  <button @click="addLike">좋아요 {{ likes }}</button>   <!-- 축약형 -->

  <input @keyup="showKey">
  <input @keyup.enter="addLike">   <!-- Enter 키를 뗄 때만 실행 -->
</template>
```

- `v-on:이벤트명="함수"` = `@이벤트명="함수"`. 프로젝트 안에서는 **한 가지로 통일**하기.
- 함수 이름만 쓰면 이벤트 객체(`event`)가 첫 번째 매개변수로 자동 전달된다.
- `@keyup.enter`처럼 **수식어**를 붙여 특정 키에만 반응하게 할 수 있다.
- Vue 공식 문서 예제는 `function` 키워드를 주로 쓴다.

### 지난주 JS와 비교

| 순수 JavaScript | Vue |
|---|---|
| `querySelector`로 요소 찾기 | 필요 없음 |
| `addEventListener('click', fn)` | `@click="fn"` |
| `el.textContent = 값` | state만 바꾸면 화면 자동 반영 |

> Vue에서는 **DOM을 직접 건드리지 않고 state(데이터)만 바꾼다.** 화면 갱신은 Vue가 알아서 한다.

## 7. Vue 코드 작성 방식 3가지

| 방식 | 특징 |
|---|---|
| `<script setup>` | Vue 3 **권장**. 가장 간결 (npm 프로젝트에서 사용) |
| `setup()` 함수 | Vue 3 Composition API 기본형. 템플릿에서 쓸 값을 **`return`으로 내보내야** 함 |
| Options API (`data`, `methods`) | Vue 2 전통 방식 |

### CDN + setup() 방식 (오늘 실습)

```html
<div id="app">
  <p>{{ count }}</p>
  <button @click="increase">+1</button>
</div>

<script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
<script>
  const { createApp, ref } = Vue           // 구조 분해 할당

  createApp({
    setup() {
      const count = ref(0)
      function increase() {
        count.value++
      }
      return { count, increase }           // ⭐ return 안 하면 템플릿에서 못 씀
    },
  }).mount('#app')
</script>
```

### NPM 방식 vs CDN 방식

| | NPM | CDN |
|---|---|---|
| 설치 | `npm install`로 내 프로젝트에 설치 | `<script src="...">`로 외부 서버에서 불러옴 |
| 장점 | 빌드 도구, 컴포넌트 파일(`.vue`) 사용 가능 | 설치 없이 HTML 파일 하나로 바로 실습 |
| 단점 | 처음 설정이 필요 | 외부 서버 상태·버전 변경에 영향받음 |
| 용도 | 실제 프로젝트 | 간단한 테스트, 학습 |

## 헷갈렸던 점 / 기억할 것
- script 안에서는 `.value`, template 안에서는 `.value` 없이.
- `setup()` 방식은 `return`에 넣은 것만 템플릿에서 쓸 수 있다. 빠뜨리면 화면에 아무것도 안 나온다.
- 사용자 입력은 `v-model`(양방향). 나중에 배울 `v-bind`는 state → 화면 한 방향이라 입력값을 받을 수 없다.
- CDN 방식에서 `<p>` 안에 `<div>`를 넣으면 브라우저가 `<p>`를 미리 닫아 버려서 구조가 깨질 수 있다. 감쌀 때는 `<div>`를 쓰자.
