## 1. 개념 정리

### REST API
- **URL은 "무엇을"**, **HTTP 메서드는 "어떻게"** 를 나타내도록 일관되게 설계한 API.
- URL에는 동사 대신 **명사(자원)** 를 쓴다.

| 요청 | 의미 |
|---|---|
| `GET /books/` | 책 목록 조회 |
| `GET /books/3/` | 3번 책 조회 |
| `POST /books/3/comments/` | 3번 책에 댓글 작성 |
| `PUT /comments/7/` | 7번 댓글 수정 |
| `DELETE /comments/7/` | 7번 댓글 삭제 |

❌ REST답지 않은 예: `GET /getAllBooks`, `POST /deleteComment?id=7` → URL에 동작(동사)이 들어가 있음

### DRF (Django REST Framework)
Django로 **JSON을 주고받는 API 서버**를 쉽게 만들게 도와주는 라이브러리.
- 지금까지: 요청 → **HTML(템플릿)** 으로 응답
- DRF부터: 요청 → **JSON 데이터**로 응답 (화면은 Vue 같은 프론트엔드가 담당)

DRF가 해 주는 일
1. Serializer로 데이터 변환 (직렬화 / 역직렬화)
2. 유효성 검사와 에러 응답
3. 인증(누구인지)·권한(무엇을 할 수 있는지) 처리

### Serializer — 파이썬 객체 ↔ JSON 번역기

| | 방향 | 언제 |
|---|---|---|
| **직렬화** (Serialization) | 모델 인스턴스·쿼리셋 → JSON | 서버가 **응답**할 때 (GET) |
| **역직렬화** (Deserialization) | JSON → 검증된 파이썬 데이터 → 저장 | 클라이언트가 보낸 데이터를 **받을** 때 (POST, PUT) |

> 기억법: 서버 밖으로 **내보낼 때 직렬화**, 서버 안으로 **들일 때 역직렬화**.

## 3. 모델과 관계

```python
from django.db import models

class Author(models.Model):
    name = models.CharField(max_length=50)

class Book(models.Model):
    authors = models.ManyToManyField(Author, related_name='books')   # M:N
    title = models.CharField(max_length=100)
    summary = models.TextField()

class Comment(models.Model):
    book = models.ForeignKey(Book, on_delete=models.CASCADE)          # 1:N
    content = models.TextField()
```

| 관계 | 필드 | 정참조 | 역참조 |
|---|---|---|---|
| Book ↔ Author (M:N) | `ManyToManyField` | `book.authors` | `author.books` (`related_name` 지정) |
| Book → Comment (1:N) | `ForeignKey` | `comment.book` | `book.comment_set` (기본 이름: `모델명소문자_set`) |

- M:N은 **중개 테이블**(`books_book_authors`)이 자동으로 만들어진다.
- `related_name`을 주면 역참조 이름이 `author.book_set` 대신 `author.books`가 된다.

## 4. Serializer 작성

`books/serializers/` 폴더를 만들고 모델별로 파일을 나눴다.
이름 규칙: **목록용은 `~ListSerializer`**, **상세용은 `~Serializer`**

### 기본형: ModelSerializer

```python
from rest_framework import serializers
from ..models import Book

class BookListSerializer(serializers.ModelSerializer):
    class Meta:
        model = Book
        fields = ('id', 'title',)     # 목록에서는 필요한 필드만
```

- `fields = '__all__'`: 모든 필드
- `fields = ('a', 'b')`: 원하는 필드만 (**튜플이면 끝에 쉼표!** `('title')`은 그냥 문자열)

### 중첩 Serializer: 관련 데이터 같이 보여주기

```python
from ..models import Book, Author, Comment

class BookSerializer(serializers.ModelSerializer):
    class AuthorNameSerializer(serializers.ModelSerializer):
        class Meta:
            model = Author
            fields = ('name',)

    class CommentListSerializer(serializers.ModelSerializer):
        class Meta:
            model = Comment
            fields = ('id', 'content',)

    # 필드 이름 = 모델에서 접근하는 이름과 같아야 한다
    authors = AuthorNameSerializer(many=True, read_only=True)       # book.authors
    comment_set = CommentListSerializer(many=True, read_only=True)  # book.comment_set

    class Meta:
        model = Book
        fields = '__all__'
```

```python
class CommentSerializer(serializers.ModelSerializer):
    class BookTitleSerializer(serializers.ModelSerializer):
        class Meta:
            model = Book
            fields = ('title',)

    book = BookTitleSerializer(read_only=True)   # 댓글 하나 → 책 하나라서 many 없음

    class Meta:
        model = Comment
        fields = '__all__'
```

| 옵션 | 언제 | 이유 |
|---|---|---|
| `many=True` | 결과가 **여러 개**일 때 (쿼리셋, 역참조, M:N) | 리스트로 직렬화 |
| `read_only=True` | **보여주기만** 하고 입력받지 않을 때 | 유효성 검사 대상에서 빠짐 |

> ⚠️ 중첩 필드 이름은 아무거나 쓰면 안 된다. `comment_set`처럼 **모델의 실제 접근 이름**과 같아야 데이터가 채워진다.

## 5. URL 설계

```python
# books/urls.py
from django.urls import path
from . import views

urlpatterns = [
    path('authors/', views.author_list),
    path('authors/<int:author_pk>/', views.author_detail),
    path('books/', views.book_list),
    path('books/<int:book_pk>/', views.book_detail),
    path('comments/', views.comment_list),
    path('books/<int:book_pk>/comments/', views.comment_create),
    path('comments/<int:comment_pk>/', views.comment_detail),   # 조회·수정·삭제
]
```

- 댓글 **생성**은 "어느 책에" 다는지가 필요해서 `books/<book_pk>/comments/`
- 댓글 **조회·수정·삭제**는 댓글 번호만 있으면 되니까 `comments/<comment_pk>/`

## 6. views.py — CRUD 구현

```python
from rest_framework.decorators import api_view
from rest_framework.response import Response
from rest_framework import status
from django.shortcuts import get_object_or_404, get_list_or_404

from .models import Author, Book, Comment
from .serializers.book import BookListSerializer, BookSerializer
from .serializers.comment import CommentListSerializer, CommentSerializer
```

- `@api_view(['GET', ...])`: 허용할 메서드 지정. 목록에 없는 메서드로 오면 **405** 자동 응답.
- `Response(데이터, status=...)`: DRF의 응답 객체 (JSON으로 변환해 줌)

### (1) 전체 조회 — 여러 개라서 `many=True`

```python
@api_view(['GET'])
def book_list(request):
    books = get_list_or_404(Book)                   # 비어 있으면 404
    serializer = BookListSerializer(books, many=True)
    return Response(serializer.data)
```

### (2) 단일 조회 — 하나라서 `many` 없음

```python
@api_view(['GET'])
def book_detail(request, book_pk):
    book = get_object_or_404(Book, pk=book_pk)
    serializer = BookSerializer(book)
    return Response(serializer.data)
```

### (3) 생성 — 역직렬화 `data=request.data`

```python
@api_view(['POST'])
def comment_create(request, book_pk):
    book = get_object_or_404(Book, pk=book_pk)
    serializer = CommentSerializer(data=request.data)
    if serializer.is_valid(raise_exception=True):
        serializer.save(book=book)        # ⭐ 외래키는 save()에서 직접 넣기
        return Response(serializer.data, status=status.HTTP_201_CREATED)
```

- `book`은 `read_only`라서 클라이언트가 보낸 값으로 채워지지 않는다 → **`save(book=book)`으로 직접 넣어 준다.**
  - 왼쪽 `book=`: 모델의 외래키 필드 이름
  - 오른쪽 `book`: URL의 `book_pk`로 찾은 실제 Book 객체
- `is_valid(raise_exception=True)`: 검증 실패 시 **400 Bad Request**와 에러 내용을 자동으로 응답.

### (4) 조회 · 수정 · 삭제 — 한 함수에서 메서드로 분기

```python
@api_view(['GET', 'PUT', 'DELETE'])
def comment_detail(request, comment_pk):
    comment = get_object_or_404(Comment, pk=comment_pk)

    if request.method == 'GET':
        serializer = CommentSerializer(comment)
        return Response(serializer.data)

    elif request.method == 'PUT':
        # (수정할 대상, 새 데이터, 일부만 수정 허용)
        serializer = CommentSerializer(comment, data=request.data, partial=True)
        if serializer.is_valid(raise_exception=True):
            serializer.save()
            return Response(serializer.data)

    elif request.method == 'DELETE':
        comment.delete()
        return Response(status=status.HTTP_204_NO_CONTENT)
```

- `partial=True`: 보낸 필드만 수정. 없으면 **필수 필드를 전부** 보내야 검증을 통과한다.

### Serializer 인자 패턴 한눈에 보기 ⭐

| 상황 | 코드 |
|---|---|
| 여러 개 조회 | `Serializer(쿼리셋, many=True)` |
| 하나 조회 | `Serializer(객체)` |
| 생성 | `Serializer(data=request.data)` → `is_valid()` → `save()` |
| 수정 | `Serializer(객체, data=request.data, partial=True)` → `is_valid()` → `save()` |

### 응답에 값 추가하기 (예: 같은 책의 댓글 수)

```python
count = Comment.objects.filter(book=comment.book).count()
return Response({'comment': serializer.data, 'comment_count': count})
```

## 7. HTTP 상태 코드

| 코드 | 의미 | 예 |
|---|---|---|
| **200** OK | 성공 | 조회, 수정 |
| **201** Created | 새 자원 생성 | POST 생성 성공 |
| **204** No Content | 성공, 응답 본문 없음 | 삭제 |
| **400** Bad Request | 잘못된 요청 | 유효성 검사 실패 |
| **401** Unauthorized | 인증 필요 | 로그인 안 함 |
| **403** Forbidden | 권한 없음 | 남의 글 삭제 |
| **404** Not Found | 자원 없음 | 없는 pk |
| **405** Method Not Allowed | 허용 안 된 메서드 | GET만 되는데 POST |
| **500** Internal Server Error | 서버 오류 | 코드 버그 |

## 헷갈렸던 점 / 시험 전 체크리스트
- [ ] `INSTALLED_APPS`에 `'rest_framework'` 넣었나?
- [ ] 여러 개면 `many=True`, 하나면 없음
- [ ] 생성·수정은 `data=request.data` 키워드로 넘기기 (첫 번째 위치 인자는 "대상 객체" 자리)
- [ ] `save()` 전에 반드시 `is_valid()`
- [ ] 외래키는 `serializer.save(book=book)`처럼 직접 넣기 + Serializer에서 그 필드는 `read_only`
- [ ] 1:N 역참조 기본 이름은 `모델명_set`, M:N은 `related_name`으로 지정한 이름
- [ ] `fields = ('title',)` 튜플 끝 쉼표
- [ ] Postman으로 POST·PUT·DELETE 보낼 때 **URL 끝 슬래시(`/`)** 꼭 붙이기
  - Django는 슬래시 없는 주소를 슬래시 붙은 주소로 리다이렉트하는데, 이때 요청 본문이 유지되지 않아 에러가 난다.
- [ ] 204는 **본문이 없는** 응답이라 메시지를 담아도 클라이언트에 안 보일 수 있다. 삭제 메시지를 꼭 보여줘야 하면 200을 쓰는 방법도 있다.
- [ ] `get_list_or_404`는 목록이 비면 404. 빈 목록도 정상으로 보려면 `Model.objects.all()` 사용.
