## 1. 동기 vs 비동기 — 커피숍 비유

| | 동기 (Synchronous) | 비동기 (Asynchronous) |
|---|---|---|
| 커피숍 | 직원이 내 커피를 **다 만들 때까지** 다음 손님 주문을 안 받음 | 주문받고 **진동벨**을 준 뒤 바로 다음 손님 주문을 받음 |
| 코드 | 앞 작업이 끝나야 다음 줄 실행 | 오래 걸리는 작업은 맡겨 두고 다음 줄 먼저 실행 |
| 결과 | 기다리는 동안 화면이 멈춤 | 기다리는 동안에도 화면이 반응함 |


- 서버 요청, 타이머처럼 **시간이 걸리는 일**을 기다리느라 전체가 멈추지 않도록, 일단 맡겨 두고 끝나면 **알림(콜백)** 을 받아 처리하는 방식이 비동기다.

---

## 2. AJAX (Asynchronous JavaScript and XML)

- **페이지 새로고침 없이** 서버와 데이터를 주고받는 기술을 부르는 이름.
- 이름에 XML이 들어가지만 요즘은 주로 **JSON**을 주고받는다.
- 예: 지도를 드래그하면 그 부분 지도만 새로 불러오기, 좋아요 버튼 누르면 숫자만 바뀌기, 검색어 자동완성

```
[전통 방식]  요청 → 서버가 HTML 전체를 새로 보냄 → 페이지 전체 새로고침
[AJAX]      요청 → 서버가 필요한 데이터(JSON)만 보냄 → JS가 바뀐 부분만 화면에 반영
```

> 지난주 DRF로 만든 **JSON 응답 API**를 프론트엔드에서 받아 쓰는 방법이 바로 이것!

## 3. 이벤트 루프 — 싱글 스레드인데 어떻게 여러 일을 할까?

JavaScript는 **한 번에 하나의 일만** 처리하는 싱글 스레드 언어다.
그런데도 동시에 여러 일을 하는 것처럼 보이는 이유는 **브라우저가 도와주기 때문**이다.

```
┌────────────┐      오래 걸리는 일 맡기기      ┌──────────────────┐
│  Call Stack │ ───────────────────────────▶ │  Web API (브라우저) │
│ (지금 실행 중) │                              │ setTimeout, fetch, │
└────────────┘                              │ 이벤트 리스너 등    │
      ▲                                     └──────────────────┘
      │ 스택이 비면                                    │ 작업 완료
      │ 하나씩 꺼내서 올림                               ▼
┌────────────┐                              ┌──────────────────┐
│ Event Loop  │ ◀──────── 계속 확인 ───────── │    Task Queue     │
└────────────┘                              │ (끝난 콜백 대기줄)  │
                                            └──────────────────┘
```

| 구성 요소 | 역할 |
|---|---|
| **Call Stack** | 지금 실행 중인 함수가 쌓이는 곳. 한 번에 하나만 실행 |
| **Web API** | 타이머, HTTP 요청, 이벤트 대기처럼 오래 걸리는 일을 **브라우저가 대신** 처리 |
| **Task Queue** | Web API에서 끝난 일의 **콜백 함수가 줄 서서** 기다리는 곳 |
| **Event Loop** | Call Stack이 **비었는지 계속 확인**하고, 비면 큐에서 하나 꺼내 스택에 올림 |

### 실행 순서 예제

```javascript
console.log('1')

setTimeout(() => console.log('2'), 0)   // 0초여도 Web API → Task Queue를 거침

Promise.resolve().then(() => console.log('3'))

console.log('4')
```
출력
```
1
4
3
2
```

- `1`, `4`: 동기 코드라서 바로 실행
- `3`: Promise 콜백은 **마이크로태스크 큐**에 들어가서, 일반 태스크 큐보다 **먼저** 처리된다
- `2`: `setTimeout`은 0초여도 **콜 스택이 다 비고 나서야** 실행된다

## 4. 비동기 구현 문법: callback → Promise → async/await

### (1) Callback
"끝나면 이 함수 불러 줘"라고 함수를 넘기는 방식.

```javascript
setTimeout(function () {
  console.log('3초 뒤 실행')
}, 3000)
```
- 문제: 비동기 작업이 **순서대로 여러 번** 이어지면 들여쓰기가 계속 깊어진다 → **콜백 지옥**

```javascript
getUser(id, function (user) {
  getPosts(user, function (posts) {
    getComments(posts[0], function (comments) {
      // 점점 오른쪽으로...
    })
  })
})
```

### (2) Promise
"나중에 결과를 줄게"라는 **약속 객체**. 상태는 3가지.

| 상태 | 의미 | 처리 |
|---|---|---|
| pending | 대기 중 | |
| fulfilled | 성공 | `.then()` |
| rejected | 실패 | `.catch()` |

```javascript
getUser(id)
  .then(user => getPosts(user))
  .then(posts => getComments(posts[0]))
  .then(comments => console.log(comments))
  .catch(error => console.log('에러:', error))   // 어디서 실패하든 한 곳에서 처리
```
- `.then`을 **옆으로 이어 붙이는(체이닝)** 방식이라 들여쓰기가 깊어지지 않는다.

### (3) async / await
Promise를 **동기 코드처럼 위에서 아래로** 읽히게 쓰는 문법.

```javascript
async function showComments(id) {
  try {
    const user = await getUser(id)          // 끝날 때까지 이 함수 안에서만 기다림
    const posts = await getPosts(user)
    const comments = await getComments(posts[0])
    console.log(comments)
  } catch (error) {
    console.log('에러:', error)
  }
}
```
- `await`는 **`async` 함수 안에서만** 쓸 수 있다.
- 에러 처리는 `try / catch`
- `async` 함수는 항상 **Promise를 반환**한다.

## 5. 비동기 HTTP 통신: fetch vs axios

### fetch — 브라우저 내장 API

```javascript
async function getUsers() {
  const res = await fetch('/api/v1/users/')
  if (!res.ok) {                          // ⚠️ 404, 500이어도 에러로 안 넘어감
    throw new Error(`HTTP 에러: ${res.status}`)
  }
  const data = await res.json()           // JSON 본문 → JS 객체 (이것도 await 필요)
  console.log(data)
}

// POST
await fetch('/api/v1/users/', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: '연주' }),   // 직접 문자열로 바꿔서 보내야 함
})
```

### axios — 외부 라이브러리

```javascript
import axios from 'axios'

async function getUsers() {
  try {
    const res = await axios.get('/api/v1/users/')
    console.log(res.data)                 // 이미 JS 객체로 변환되어 있음
  } catch (error) {
    console.log(error.response.status)    // 4xx, 5xx면 자동으로 catch로 감
  }
}

// POST
await axios.post('/api/v1/users/', { name: '연주' })   // 객체를 그냥 넘기면 됨
```

### 비교

| | fetch | axios |
|---|---|---|
| 설치 | 필요 없음 (브라우저 내장) | 설치 필요 (`npm install axios` 또는 CDN) |
| 응답 데이터 | `await res.json()`으로 직접 변환 | `res.data`에 자동 변환 |
| 보낼 데이터 | `JSON.stringify()` + 헤더 직접 작성 | 객체 그대로 전달 |
| 4xx·5xx 응답 | **에러로 처리 안 함** → `res.ok`로 직접 확인 | 자동으로 `catch`로 넘어감 |
| 부가 기능 | 기본 기능 위주 | `baseURL`, 타임아웃, 인터셉터(요청마다 토큰 붙이기 등) |

- 두 방법 모두 `.then()` 방식과 `async/await` 방식 **둘 다** 쓸 수 있다.
- 간단한 요청은 fetch로도 충분하고, 요청이 많고 공통 설정(주소, 인증 토큰)이 필요한 프로젝트에서는 axios가 편하다.

## 헷갈렸던 점 / 기억할 것
- `setTimeout(fn, 0)`도 바로 실행되지 않는다. 콜 스택이 비어야 실행된다.
- Promise 콜백(마이크로태스크)이 `setTimeout` 콜백보다 먼저 실행된다.
- fetch는 **네트워크가 끊겼을 때만** reject된다. 404, 500은 `res.ok`로 직접 확인해야 한다.
- fetch는 `res.json()`도 Promise라서 `await`를 한 번 더 써야 한다.
- 순서대로 실행할지, 조건문·반복문 안에서 쓸지는 fetch·axios의 차이가 아니라 **`async/await`로 어떻게 쓰느냐**의 문제다.
