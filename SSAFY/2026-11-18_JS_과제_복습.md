## 1. 함수 선언식 vs 표현식 vs 화살표 함수

```javascript
// 1) 선언식
function add(a, b) {
  return a + b
}

// 2) 표현식 (변수에 함수를 담음)
const sub = function (a, b) {
  return a - b
}

// 3) 화살표 함수
const mul = (a, b) => a * b      // 한 줄이면 중괄호, return 생략 가능
const square = x => x * x        // 매개변수가 1개면 괄호 생략 가능
const makeUser = name => ({ name })  // 객체를 바로 반환할 땐 소괄호로 감싸기
```

| | 선언식 | 표현식 | 화살표 함수 |
|---|---|---|---|
| 호이스팅 | ✅ 선언 전에 호출 가능 | ❌ | ❌ |
| 자기 `this` | 있음 (호출한 방식에 따라 결정) | 있음 | **없음** (바깥 `this` 사용) |
| `new`로 생성자 사용 | 가능 | 가능 | 불가능 |

- 선언식은 코드가 실행되기 전에 **미리 등록**되어서 위에서 먼저 불러도 된다.
- 표현식과 화살표 함수는 `const` 변수에 담기 때문에 그 줄이 실행된 **뒤에만** 쓸 수 있다.
- 화살표 함수는 짧게 쓰기 좋지만, `this`가 필요한 곳(이벤트 리스너, 객체 메서드)에서는 `function`을 쓴다.

```javascript
hello()                 // ✅ 동작
function hello() { console.log('hi') }

bye()                   // ❌ ReferenceError (초기화 전 접근)
const bye = () => console.log('bye')
```

## 2. 배열 메서드

```javascript
const scores = [72, 95, 88, 40, 100]
```

| 메서드 | 하는 일 | 반환값 | 예시 결과 |
|---|---|---|---|
| `forEach(fn)` | 각 요소로 fn 실행 | 없음(`undefined`) | 출력만 |
| `map(fn)` | 각 요소를 바꿔서 **새 배열** | 같은 길이 배열 | `scores.map(s => s + 5)` → `[77, 100, 93, 45, 105]` |
| `filter(fn)` | 조건이 `true`인 요소만 | 새 배열 | `scores.filter(s => s >= 80)` → `[95, 88, 100]` |
| `find(fn)` | 조건에 맞는 **첫 요소** | 요소 하나 or `undefined` | `scores.find(s => s < 50)` → `40` |
| `some(fn)` | 하나라도 맞으면 | `true/false` | `scores.some(s => s === 100)` → `true` |
| `every(fn)` | 전부 맞으면 | `true/false` | `scores.every(s => s >= 60)` → `false` |
| `reduce(fn, 초기값)` | 하나로 누적 | 값 하나 | `scores.reduce((acc, s) => acc + s, 0)` → `395` |

```javascript
// 메서드 체이닝: 80점 이상의 평균
const high = scores.filter(s => s >= 80)
const avg = high.reduce((acc, s) => acc + s, 0) / high.length
console.log(avg)  // 94.33...
```

### 기억할 것
- `forEach`는 반환값이 없어서 결과를 변수에 담으면 `undefined`. **새 배열이 필요하면 `map`**.
- `map`, `filter`는 원본을 바꾸지 않는다. `push`, `pop`, `splice`, `sort`는 **원본을 바꾼다**.
- `reduce`는 초기값(두 번째 인자)을 꼭 넣어 주는 습관을 들이자. 빈 배열에서 에러를 막아 준다.

## 3. 이벤트 흐름: 캡처링과 버블링

이벤트는 3단계로 흐른다.

```
1. 캡처링 단계: window → document → ... → 부모  (위에서 아래로 내려감)
2. 타깃 단계:   실제로 클릭한 요소
3. 버블링 단계: 부모 → ... → document → window  (아래에서 위로 올라감)
```

- `addEventListener`는 기본적으로 **버블링 단계**에서 실행된다.
- 세 번째 인자로 `{ capture: true }`(또는 `true`)를 주면 **캡처링 단계**에서 실행된다.

```html
<div id="outer">
  <button id="inner">클릭</button>
</div>

<script>
  const outer = document.querySelector('#outer')
  const inner = document.querySelector('#inner')

  outer.addEventListener('click', () => console.log('outer - 캡처링'), { capture: true })
  outer.addEventListener('click', () => console.log('outer - 버블링'))
  inner.addEventListener('click', () => console.log('inner - 타깃'))
</script>
```
버튼 클릭 시 출력 순서
```
outer - 캡처링
inner - 타깃
outer - 버블링
```

| 메서드 | 하는 일 |
|---|---|
| `event.stopPropagation()` | 이벤트가 **다른 요소로 전파되는 것**을 멈춤 |
| `event.preventDefault()` | 브라우저의 **기본 동작**을 막음 (전파와는 상관없음) |

> 둘은 이름이 비슷하지만 하는 일이 완전히 다르다. 전파를 막는 것 vs 기본 동작을 막는 것.

## 4. 이벤트 핸들러로 DOM 조작하기 — 테마 전환

핵심 아이디어: **스타일은 CSS 클래스에 미리 정의**해 두고, JS는 **클래스만 붙였다 뗐다** 한다.

```html
<style>
  body { background: white; color: black; }
  body.dark { background: #222; color: #eee; }
</style>

<button id="theme-btn">🌙 다크 모드</button>

<script>
  const themeBtn = document.querySelector('#theme-btn')

  themeBtn.addEventListener('click', function () {
    const isDark = document.body.classList.toggle('dark')  // 추가되면 true
    themeBtn.textContent = isDark ? '☀️ 라이트 모드' : '🌙 다크 모드'
  })
</script>
```

- `classList.toggle`의 반환값(`true/false`)으로 현재 상태를 알 수 있어서 버튼 글자까지 한 번에 바꿀 수 있다.
- `element.style.background = ...`로 직접 바꾸는 것보다 클래스 방식이 **CSS와 JS 역할이 분리**되어 관리하기 쉽다.

### classList 정리
| 메서드 | 하는 일 |
|---|---|
| `add('a')` | 클래스 추가 |
| `remove('a')` | 클래스 제거 |
| `toggle('a')` | 있으면 제거, 없으면 추가 (결과를 `true/false`로 반환) |
| `contains('a')` | 있는지 확인 (`true/false`) |

## 5. 종합: Todo 리스트 (추가 · 완료 · 삭제)

어제 배운 내용을 다 합쳐서 쓰는 연습. 내가 이해한 구조를 정리하면:

```html
<form id="todo-form">
  <input type="text" id="todo-input">
  <button>추가</button>
</form>
<ul id="todo-list"></ul>

<script>
  const form = document.querySelector('#todo-form')
  const input = document.querySelector('#todo-input')
  const list = document.querySelector('#todo-list')

  // 1) 추가: submit 이벤트 + preventDefault + createElement
  form.addEventListener('submit', function (event) {
    event.preventDefault()
    const text = input.value.trim()
    if (!text) return

    const li = document.createElement('li')
    const span = document.createElement('span')
    span.textContent = text            // 사용자 입력은 textContent로!

    const delBtn = document.createElement('button')
    delBtn.textContent = '삭제'
    delBtn.classList.add('delete-btn')

    li.append(span, delBtn)
    list.appendChild(li)
    form.reset()
  })

  // 2) 완료·삭제: ul 하나에 이벤트 위임
  list.addEventListener('click', function (event) {
    const li = event.target.closest('li')
    if (!li) return

    if (event.target.classList.contains('delete-btn')) {
      li.remove()                      // 삭제
    } else {
      li.classList.toggle('done')      // 완료 표시
    }
  })
</script>
```

### 배운 점
- **이벤트 위임** 덕분에 나중에 추가된 li에도 리스너를 따로 달 필요가 없다.
- `event.target.closest('li')`: 클릭한 요소에서 **가장 가까운 조상 li**를 찾아 준다. span을 눌러도 li를 정확히 잡을 수 있다.
- `li.remove()`: 요소 스스로 DOM에서 빠진다.
- `append`는 여러 개를 한 번에 붙일 수 있고, `appendChild`는 하나만 붙인다.

## 헷갈렸던 점 / 기억할 것
- 화살표 함수 콜백 안에서 `this`를 쓰면 요소가 아니라 바깥 `this`(보통 `window`)가 나온다 → 이벤트 리스너는 `function` 또는 `event.currentTarget` 사용.
- `stopPropagation`(전파 막기) ≠ `preventDefault`(기본 동작 막기)
- `forEach`는 반환값 없음, `map`은 새 배열 반환.
